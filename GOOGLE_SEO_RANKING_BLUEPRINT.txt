1. HOW GOOGLE SEARCH WORKS: THE THREE CORE STAGES
================================================================================
Reference: https://developers.google.com/search/docs/fundamentals/how-search-works

Google Search is an automated, continuous, three-stage processing pipeline:

STAGE 1: CRAWLING (Discovery & Retrieval)
- Googlebot discovers URLs through links on existing known pages, XML sitemaps, 
  and manual submissions via the Search Console URL Inspection tool.
- Googlebot respects robots.txt directives. If a path is disallowed, Googlebot 
  will not fetch the file content.
- Googlebot prioritizes crawling based on crawl budget, server response latency, 
  page update frequency, and link equity.
- For new websites, Google starts with conservative crawling to measure server 
  stability before increasing crawl cadence.

STAGE 2: INDEXING (Rendering, Parsing & Understanding)
- Googlebot analyzes textual content, key heading tags (h1-h3), image alt 
  attributes, and structural HTML.
- Headless Chromium Rendering: Google renders JavaScript. However, client-side 
  rendering (pure SPAs) adds significant indexing latency (the "render queue").
  * OUR ADVANTAGE: FundedTradingRules.com uses Static Site Generation (SSG) 
    via scripts/prerender.tsx. All 96 pages exist as complete static HTML files, 
    allowing immediate indexing without waiting for the JavaScript render queue.
- Canonicalization: Google determines the primary version of each page. It uses 
  the canonical link tag, sitemap inclusion, internal links, and URL structure 
  to prevent duplicate content indexing.
- Structured Data: Google extracts JSON-LD Schema.org graphs to understand entity 
  relationships (Organization, WebSite, TechArticle, FAQPage, AggregateRating).

STAGE 3: SERVING & RANKING (Query Matching & Algorithmic Scoring)
- When a user enters a search query (e.g. "best funded accounts 2026" or 
  "ftmo daily drawdown rule"), Google algorithms retrieve matching pages from 
  the index.
- Ranking is determined by hundreds of signals:
  1. Content Relevance: Exact and semantic term matching with user intent.
  2. Content Quality (E-E-A-T): Experience, Expertise, Authoritativeness, and 
     Trustworthiness.
  3. User Experience: Page speed, mobile responsiveness, HTTPS security.
  4. Engagement Signals: Click-through rate (CTR), bounce rate, dwell time.
  5. Backlink Authority: Quality and relevance of external referring domains.

2.1. THE SITEMAPS REPORT & FIXING THE "1 ERROR"
Reference: https://support.google.com/webmasters/answer/7450883

* THE PROBLEM IN SEARCH CONSOLE:
  Under "Submitted sitemaps", the URL shows "https://www.fundedtradingrules.com/" 
  with Status: "1 error" and Type: "Unknown".

* THE EXACT CAUSE:
  The root homepage URL (https://www.fundedtradingrules.com/) was submitted into 
  the "Add a new sitemap" box instead of the XML sitemap filename (sitemap.xml).
  When Google's sitemap parser requested the root URL, it received an HTML 
  document (<!doctype html>...), triggering Google's fatal parsing error:
  "Your Sitemap appears to be an HTML page. Please use a supported sitemap format."

* THE STEP-BY-STEP FIX:
  1. In Google Search Console, go to Indexing -> Sitemaps.
  2. Under "Submitted sitemaps", click the erroneous entry ending in "/".
  3. In the upper right corner, click the three vertical dots (⋮) and select 
     "Remove sitemap".
  4. In the top input box ("Add a new sitemap"), enter exactly:
     sitemap.xml
  5. Click SUBMIT.
  6. Search Console will ping https://www.fundedtradingrules.com/sitemap.xml.
     Googlebot will read the valid <urlset> and index all 96 discovered pages.

3. WHY PAGES GO MISSING OR FAIL TO INDEX (GOOGLE'S 9 REASONS)
================================================================================
Reference: https://support.google.com/webmasters/answer/9133276

Google outlines 9 distinct reasons why a page may be missing from search results:

1. THE SITE IS BRAND NEW (Most common):
   Google hasn't crawled and indexed the site yet. It takes time for Google to 
   discover a new site. Submitting a sitemap and requesting indexing accelerates this.

2. NO INTERNAL OR EXTERNAL LINKS:
   Googlebot follows links across the web. If a page has no incoming links 
   (an "orphan page"), Googlebot cannot discover it.
   * OUR STATUS: All 96 pages have deep cross-linking in the footer, navigation, 
     and page body (over 9,900 internal links across the site).

3. ROBOTS.TXT BLOCKING:
   If robots.txt has "Disallow: /", Google is barred from reading the page.
   * OUR STATUS: Fully open ("Allow: /").

4. 'NOINDEX' DIRECTIVE:
   If HTML contains a noindex robots meta tag, Google drops the page from the index.
   * OUR STATUS: Only 404.html contains noindex (correct). All 96 content routes 
     have index, follow enabled.

5. TECHNICAL / SERVER ERRORS (5xx):
   If the hosting server crashes or times out when Googlebot requests the page, 
   Google aborts indexing.
   * OUR STATUS: Hosted on Vercel Global Edge CDN with 99.99% uptime and sub-200ms 
     TTFB (Time to First Byte).

6. MANUAL ACTIONS / SECURITY ISSUES:
   Penalties for spam, malware, deceptive cloaking, or scraped content.
   * OUR STATUS: 100% clean. No penalties.

7. CANONICAL MISMATCH:
   If Google determines two pages are duplicates, it indexes only the canonical.
   * OUR STATUS: 100% of pages contain self-referencing canonical tags.

8. DISCOVERED — CURRENTLY NOT INDEXED:
   Google knows the URL exists (from sitemap or links), but hasn't crawled it 
   yet due to crawl queue scheduling.
   * ACTION: Request indexing via URL Inspection tool.

9. CRAWLED — CURRENTLY NOT INDEXED:
   Google visited the page but decided not to index it because of thin content, 
   low value, or poor quality signals.
   * OUR STATUS: Every page contains rich, deterministic data, comprehensive 
     tables, and substantial word counts (>40KB to >180KB per document).

4. ARCHITECTURAL BLUEPRINT FOR THIS PLATFORM (FUNDEDTRADINGRULES.COM)
================================================================================

4.1. PRE-RENDERING (SSG) VS CLIENT-SIDE HYDRATION
- The fatal flaw of many React/Next.js/Vite websites is serving an empty 
  root container, forcing Googlebot to execute client JavaScript.
- FundedTradingRules.com executes scripts/prerender.tsx during "npm run build".
- It renders the entire React component tree into raw HTML strings inside dist/.
- When Googlebot visits any of the 96 routes, it receives 100% complete HTML 
  immediately, including tables, rule breakdown matrices, headings, and JSON-LD.
- When human users visit the site, src/main.tsx detects existing HTML nodes and 
  executes ReactDOM.hydrateRoot(), attaching instant interactive client behavior.

4.2. KEYWORD MAPPING & SEMANTIC ARCHITECTURE
The site is built on a high-authority "Hub-and-Spoke" architectural model:

PILLAR HUB 1: CORE DIRECTORY (/prop-firms)
- Primary Keywords: "best funded accounts", "prop trading firms", "prop firm list 2026"
- Spokes: 24 dedicated firm dossiers (/prop-firms/ftmo, /prop-firms/topstep, etc.)

PILLAR HUB 2: MASTER RULE MANUAL (/rules)
- Primary Keywords: "funded rules", "prop firm trading rules", "funded account rules"
- Spokes: 41 in-depth rule guides (/rules/daily-drawdown, /rules/trailing-drawdown, 
  /rules/consistency-rule, /rules/news-trading-restrictions, etc.)

PILLAR HUB 3: COMPARISON MATRIX (/compare)
- Primary Keywords: "prop firm comparison", "ftmo vs topstep", "ftmo vs funding pips"
- Spokes: 10 curated head-to-head showdowns (/compare/ftmo-vs-topstep, etc.)

PILLAR HUB 4: CURATED ATTRIBUTE DIRECTORIES (/prop-firms/with-*)
- Primary Keywords: "prop firms with static drawdown", "prop firms with instant funding",
  "prop firms no consistency rule", "prop firms allow news trading"
- Spokes: Filtered indexes targeting high-intent long-tail buyers.

4.3. STRUCTURED DATA (SCHEMA.ORG) GRAPH
Every pre-rendered page includes an explicit JSON-LD graph:
- Organization Schema: Declares corporate entity, 512x512 logo, customer support point.
- WebSite Schema: Declares search action endpoint (/rules?q={search_term}).
- BreadcrumbList Schema: Explicit hierarchy on every sub-route for rich SERP breadcrumbs.
- TechArticle Schema: Attached to all 41 rule guides with headline, author, and dates.
- FAQPage Schema: Embedded on the homepage and rules hub, qualifying the site for 
  Google Featured Snippets and People Also Ask (PAA) accordions.
- AggregateRating Schema: Attached to firm dossiers citing verified review metrics.

4.4. E-E-A-T & THE HELPFUL CONTENT SYSTEM
Google's Helpful Content System rewards:
1. First-hand evidence: Every rule cites official contracts and TOS sections.
2. Epistemic Segregation: Trader complaints and Trustpilot reviews are strictly 
   segregated from official firm rules, proving editorial objectivity.
3. Deterministic Math: Exact formulas for balance-based vs equity-based trailing 
   drawdown, eliminating ambiguity.
4. Transparency: Clear corporate leadership, founding year, operating country, 
   and full platform support tables.

4.5. GEO & AEO (GENERATIVE & ANSWER ENGINE OPTIMIZATION)
Google AI Overviews, Perplexity, and ChatGPT Search index sites differently than 
traditional search engines. They look for factual density and direct answers:
- llms.txt & llms-full.txt: Clean markdown documentation hosted at root domain 
  providing AI agents with instant machine-readable knowledge.
- Question-Answer Headings: H2 and H3 tags phrased as natural language questions 
  ("What is the difference between balance and equity drawdown?").
- Direct Definition Paragraphs: 40-to-60-word concise explanations directly below 
  each heading for instant snippet extraction.
